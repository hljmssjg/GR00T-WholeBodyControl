### 2.5 `observation.cpp_rotation_offset` 的准确含义

字段名里带 `offset`，但它不是传感器标定 offset，也不是 base IMU 和 torso IMU 之间的相对旋转。它来自 C++ 侧的：

```cpp
init_ref_data_root_rot_array_
```

更准确的含义是：

```text
reference motion 在初始化 / heading reset 时刻的 root 旋转四元数
```

C++ 在初始化 heading 或回到 reference motion 第 0 帧时，会把当前 reference motion 的 root quaternion 保存下来：

```cpp
const auto motion_body_quat_init = current_motion_->BodyQuaternions(current_frame_);
init_ref_data_root_rot_array_ = motion_body_quat_init[0];
```

后续它用于把 reference motion 的朝向对齐到真机初始化时的 base heading。核心关系可以理解为：

```text
apply_delta_heading
= 机器人初始化 base heading
  × reference motion 初始 root heading 的逆
  × 用户额外 delta heading
```

然后目标 root/base 姿态大致按下面方式生成：

```text
base_quat_target = apply_delta_heading × 当前 reference motion root quat
```

所以这个字段对失败分析的用途是：判断目标动作朝向是否因为 heading reset、reference frame、delta heading 等原因被整体旋转错了。它一般不是硬件状态量，也不表示真机当前姿态。

## 8. 跨目录对齐关系

### 8.1 Parquet 和视频

同一个 `episode_index` 对应：

```text
data/chunk-000/episode_{episode_index:06d}.parquet
videos/chunk-000/observation.images.ego_view/episode_{episode_index:06d}.mp4
```

视频 fps 和 parquet fps 都是 `50 Hz`，理论上可以用 episode 内 `timestamp` / `frame_index` 对齐。

### 8.2 数据集 events 和 parquet

`meta/events.jsonl` 记录采集按键、episode 开始、保存、成功失败等事件。保存结果最终落在：

```text
meta/episode_outcomes.jsonl
```

该文件是 episode 成功失败标签的最直接来源。

### 8.3 Inference trace 和 parquet

`inference_trace/published_actions.jsonl` / `chunks/*.npz` 记录 policy 发布侧的 action chunk。parquet 中的 `action.motion_token`、`teleop.left_hand_joints`、`teleop.right_hand_joints`、`action.wbc` 是 exporter 合并到数据集里的逐帧记录。

跨进程精确对齐建议使用：

| parquet 字段 | process trace 字段 |
|---|---|
| `diagnostic.exporter_timestamp_s` | `published_actions.time_unix_s` |
| `diagnostic.sonic_age_ms` | `published_actions.time_unix_s` / chunk event time |
| `timestamp` | episode 内视频时间 |
| `index` | 数据集全局帧 |

仅靠 `frame_index` 可能错位，因为不同进程里的 frame index 语义不同。

## 9. 对失败分析最有用的字段

当前这批日志已经能支持以下诊断：

| 诊断目标 | 主要字段 |
|---|---|
| 判断成功 / 失败 | `meta/episode_outcomes.jsonl` |
| 定位异常时间 | `timestamp`, `frame_index`, ego view video |
| 观察真机姿态 | `observation.state`, `observation.eef_state`, `root_orientation`, `torso_orientation` |
| 观察目标动作是否过激 | `action.wbc`, `action.motion_token`, `teleop.left_hand_joints`, `teleop.right_hand_joints` |
| 计算 tracking error | `action.wbc - observation.state` |
| 观察手臂 / 手指是否跟不上 | `observation.state` vs `action.wbc` 的 arm / hand 分组 |
| 观察时延和不同步 | `diagnostic.state_age_ms`, `camera_age_ms`, `image_state_delta_ms`, `sonic_age_ms` |
| 观察硬件异常 | `motor_error`, `motor_temperature`, `motor_torque` |
| 观察推理是否卡顿 | `inference_trace/events.jsonl` 里的 `inference_ms` |
| 观察 action chunk 输出 | `inference_trace/chunks/*.npz`, `published_actions.jsonl` |

## 10. 当前缺失或不足的信号

这些目录里目前没有直接保存：

| 缺失信号 | 影响 |
|---|---|
| 足底接触 / 足底力 | 很难直接判断打滑、离地、接触切换失败 |
| base 世界坐标平移 | MuJoCo / URDF 回放只能固定 root 或近似 root，高度和漂移不可靠 |
| 物体位姿 | 很难自动判断小熊是否被抓住、是否进入袋子 |
| wrist camera | 抓取阶段的手眼细节不足 |
| depth / 点云 | 难以做空间关系和碰撞分析 |
| 真实低层 PD target / torque command 细节 | 很难完整解释 `action.wbc` 到真机姿态之间的 tracking failure |
| 手指独立 torque / tactile / contact | 很难判断 DEX3-1 是否真的接触、夹住或打滑 |

因此当前最现实的第一版 failure agent 输入应围绕：

1. 视频人工标注阶段和异常时间。
2. `action.wbc` 与 `observation.state` 的 tracking error。
3. `motion_token` / hand target 的突变。
4. latency diagnostic。
5. motor error / torque / temperature。

后续如果要让系统从“解释失败”走向“纠正下次部署”，建议补齐接触、物体状态、世界坐标 root pose、wrist/depth 视觉中的至少一部分。
