## 4. 录到的数据 schema（每帧 50 Hz）

| 字段 | 维度 | 说明 |
|---|---|---|
| `action.motion_token` | **64** | **N1.7 学习的主目标**——SONIC 的 latent |
| `action.wbc` | 全身关节 | 备份的关节目标 |
| `observation.state.joint_position` | N | 实测关节角 |
| `observation.state.joint_velocity` | N | 实测关节速度 |
| `observation.state.body_rotation_6d` | 6 | base 朝向 |
| `observation.state.projected_gravity` | 3 | 重力方向 |
| `observation.images.ego_view` | 480×640×3 | 头部相机 |
| `observation.images.left_wrist`、`right_wrist` | 同上 | 可选（手腕相机） |
| `teleop.smpl_pose` | 63 | 操作员实时 SMPL 参数 |
| `teleop.stream_mode` | 1 | 当前模式（POSE=1 / VR_3PT=5 等） |
| `annotation.human.action.task_description` | string | 语言指令 |

## 5. N1.7 vs N1.5/N1.6 的根本差异

```
N1.5/N1.6:  VLA → 手腕末端位置 → IK + 下肢 RL → 关节
N1.7:       VLA → 64 维 token  → SONIC 解码器 → 全身关节
```

- N1.5/N1.6 录的是**末端执行器位置**（左/右手腕的位置+四元数），没有 token 概念
- N1.7 录的是 **SONIC C++ 实时吐出的 64 维 latent token**
- 两代不是"加了 encoder"的关系，是**完全不同的动作抽象**

---

## 6. 64 维 token 怎么产生的

**关键事实：token 由 SONIC C++ 部署进程内置的 encoder ONNX 模型实时生成**，Python 数采端只是把它从 ZMQ 上接住写进 parquet。

每个 50Hz 控制周期，C++ 跑三个 ONNX：

```
① 规划器 ONNX       (输入: 操作员 ZMQ 指令)
       ↓
   下肢 10 帧 motion 轨迹
       ↓
② encoder ONNX     (输入: 下肢轨迹 + 上肢 teleop 目标)
       ↓
   64 维 token
       ↓
③ policy ONNX      (输入: token + 历史观测)
       ↓
   全身关节命令 → 电机
       ↓
   LogPostState(token) → ZMQ 5557 → run_data_exporter 写 parquet
```

**Encoder 是模式感知的**（[observation_config.yaml](../gear_sonic_deploy/policy/release/observation_config.yaml)）：

| mode_id | 名字 | 对应 teleop 模式 | encoder 输入 |
|---|---|---|---|
| 0 | `g1` | PLANNER / PLANNER_FROZEN_UPPER | 全身 motion 轨迹 |
| 1 | `teleop` | **VR_3PT** | 下肢轨迹 + 3 点上肢 |
| 2 | `smpl` | **POSE** | 全身 SMPL 关节 |

**所有模式都输出 64 维 token，schema 完全一致。**

## 7. 三种采集方式对比

| 维度 | 三点法 VR_3PT | 带脚环 POSE（官方主推） | 动捕 |
|---|---|---|---|
| 硬件 | PICO 4 + 2 手柄 | PICO 4 + 2 手柄 + **2 脚环** | Vicon / Xsens / Rokoko |
| 价格 | ~$500 | ~$700-800 | $5,000 - $200,000+ |
| 追踪点 | 头 + 双手腕（3 点） | 全身 SMPL 24 关节 | 全身高密度 |
| 下半身 | SONIC 规划器自动生成 | **操作员真实动作直接映射** | 类似 POSE 但精度更高 |
| 能采的动作 | 上肢操作 + 固定走/跑风格 | **任意全身**：蹲、单腿、跨步、起身 | 任意全身 |
| encoder 模式 | mode 1 | mode 2 | （不参与真机） |
| 校准 | 复杂：每次进 VR_3PT 都要重校手腕 | 中等：开场一次 | 简单 |
| 官方地位 | 备用模式 | **默认推荐** | 不用于 N1.7 真机 |

### 动捕在 SONIC 工作流里的位置

动捕**不参与 N1.7 真机数据采集**，它出现在更上游：

```
[1] SONIC 底座训练（一次性，离线）
    Bones-SEED 数据集（142K 动捕，~288h）→ IsaacLab RL → SONIC 跟踪策略

[2] N1.7 VLA 微调（每个任务做一次）
    PICO + 脚环（或三点法）真机遥操 → LeRobot 数据 → 微调 N1.7

[3] 真机部署
    N1.7 出 token → SONIC 出关节 → G1（无操作员）
```

**不在真机采集用动捕的原因**：
1. 动捕房里看不到机器人视角，无法形成视觉闭环
2. VR 手柄自带 trigger/grip 控制 Dex3 手开合，动捕没有
3. 动捕房间体积有限，VR inside-out 可大范围活动

## 8. 官方 N1.7 真机用什么

**结论：PICO 4 + 2 手柄 + 2 脚环，POSE 模式（带脚环）**。

证据：
- 安装文档强制要求脚环（[vr_teleop_setup.md](../docs/source/getting_started/vr_teleop_setup.md)）
- 教程主流程 A+X 切到 POSE 模式
- README 演示视频里有蹲、跨步、起身、跳——VR_3PT 做不到这些
- 操作员手册明说 "policy will copy your motion including foot movements"

---

## 9. 关于 Quest Pro 的可行性（如果不买 PICO）

整套 SONIC + N1.7 的 VR 前端**只支持 XRoboToolkit SDK**（`xrobotoolkit_sdk`，缩写 `xrt`）。该 SDK **只有 PICO 的官方 APK**，Meta Quest 没有直接支持。

可行路线：写一个**假 xrt 模块**（同名同接口的 Python 包），内部从已调通的 Quest 库（如 `xr_teleoperate/televuer`）取头/手 pose，伪造一个 24×7 SMPL 数组。下游代码 0 改动。

代价：
- 写约 200 行 shim
- 处理坐标系对齐（Unity 左手 Y-up → 机器人右手 Z-up）
- 三点法可行，但**官方默认的 POSE 模式（带脚环）做不了**——Quest Pro 没有脚部追踪硬件

---

## 10. 下一步建议

1. **先借/买一台 PICO 4 + 2 手柄**，跑通官方 POSE 模式数据采集
2. 决定脚环要不要买：
   - 想采全身丰富动作（蹲、跨、起身）→ **必须买脚环**
   - 只采桌面/上肢操作 → **三点法够用，可省脚环**
3. 跑通后再考虑 Quest Pro 替换方案（写 fake xrt shim）
