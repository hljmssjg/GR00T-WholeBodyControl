# 相机方案调研 — N1.7 + SONIC

> 围绕"换哪种相机 / 用几个 / 改哪里 / 能不能直接 fine-tune 官方 checkpoint"四个问题。

---

## 1. 官方配置（结论先行）

| 维度 | 官方 |
|---|---|
| **主线相机数** | **1 个**（头部 ego_view） |
| **可选扩展** | 最多 +2（左/右腕） |
| **型号** | Luxonis OAK（OAK-D / OAK-1） |
| **G1 出厂的 RealSense D435** | ❌ 不使用，URDF 里只是 Unitree 自带的 `d435_link` |
| **物理连接** | 全部 USB 接到 **G1 机身的 Jetson Orin**，不接工作站 |
| **数据通路** | Jetson 跑 `composed_camera_server` → MJPEG → ZMQ:5555 → 工作站消费 |

**证据**：
- [features_sonic_vla.py:196-198](../gear_sonic/data/features_sonic_vla.py#L196-L198) 默认 modality video 只有 `ego_view`
- `record_wrist_cameras: bool = False` 默认值
- [data_collection.md:10-13](../docs/source/tutorials/data_collection.md#L10-L13) "tested and supported = OAK；wrist = optional"
- 所有 G1 URDF 都有 `d435_link`（出厂硬件），无任何 `oak_link`（外接）
- [install_camera_server.sh](../install_scripts/install_camera_server.sh) 默认只装 depthai SDK
- 仓库无 3D 打印夹具 / CAD —— 物理改装方案未公开

## 2. 三种方案对比

| 方案 | 头部 | 左腕 | 右腕 | 代码改动 | 直接 finetune N1.7-3B | 推荐度 |
|---|---|---|---|---|---|---|
| **A. 单头**（官方主线） | USB 双目（取左眼） | — | — | ~50 行（仅 USB 驱动） | ✅ 一字不改 | ⭐⭐⭐ |
| **B. 头 + 左腕** | USB 双目（取左眼） | RealSense D405 | — | ~150 行（含 schema 拆 flag） | ⚠️ 需改 modality + LoRA | ⭐⭐ |
| **C. 头 + 双腕**（官方扩展） | OAK | OAK | OAK | 仅 launcher 加 `--record-wrist-cameras` | ⚠️ 需改 modality | ⭐ |

**Domain shift 风险**：USB 双目 vs OAK 主要差 **FOV / 畸变 / 色彩**，FOV 90°~100° 的双目相机最接近 OAK。Fine-tune 数据建议 100-200 段（官方 50-100 是基于 OAK 的）。

## 3. 方案 A —— 单头 USB 双目（推荐起步）

### 改动清单（仅 2 个文件）

**[gear_sonic/camera/drivers/usb_camera.py](../gear_sonic/camera/drivers/usb_camera.py)** —— 加双目裁切：
```python
class USBCameraConfig:
    image_dim: tuple = (640, 480)
    capture_dim: tuple | None = None     # 新增 例:(1280,480)
    stereo_mode: str = "none"            # 新增 "none"|"left"|"right"

def read(self):
    ret, frame = self.cap.read()
    if self.config.stereo_mode == "left":
        frame = frame[:, : frame.shape[1] // 2]
    elif self.config.stereo_mode == "right":
        frame = frame[:, frame.shape[1] // 2 :]
    if (frame.shape[1], frame.shape[0]) != self.config.image_dim:
        frame = cv2.resize(frame, self.config.image_dim)
    ...
```

设置 `capture_dim` 时同时打 `MJPG` fourcc，否则双目相机开不到原生 SBS 分辨率：
```python
self.cap.set(cv2.CAP_PROP_FOURCC, cv2.VideoWriter_fourcc(*"MJPG"))
```

**[gear_sonic/camera/composed_camera.py:387-395](../gear_sonic/camera/composed_camera.py#L387-L395)** —— 透传参数：
```python
elif camera_type == "usb":
    usb_config = USBCameraConfig()
    if mount_position == "ego_view":
        usb_config.stereo_mode = self.config.ego_view_stereo_mode
        usb_config.capture_dim = self.config.ego_view_capture_dim
    ...
```
`ComposedCameraConfig` 加 `ego_view_stereo_mode: str = "none"` 和 `ego_view_capture_dim: tuple | None = None`。

### 启动（Jetson 上）

```bash
python -m gear_sonic.camera.composed_camera \
    --ego-view-camera usb --ego-view-device-id 0 \
    --ego-view-stereo-mode left --ego-view-capture-dim 1280 480 \
    --port 5555
```

### 数据采集 + 微调（工作站）

**完全用默认 flag**：
```bash
python gear_sonic/scripts/launch_data_collection.py --camera-host 192.168.123.164 --task-prompt "xxx"
```
```bash
uv run python gr00t/experiment/launch_finetune.py \
    --base-model-path nvidia/GR00T-N1.7-3B \
    --embodiment-tag UNITREE_G1_SONIC \
    --modality-config-path gr00t/configs/data/embodiment_configs.py \
    ...
```

不开 `--record-wrist-cameras`，dataset schema 自动只含 `ego_view`，与 `UNITREE_G1_SONIC` embodiment 默认 modality **一字不差**。

## 4. 方案 B —— 加左腕 D405（如需精细操作）

### 额外改动（在 A 基础上）

**[gear_sonic/camera/drivers/realsense.py](../gear_sonic/camera/drivers/realsense.py)** 现有驱动的 3 个坑：
1. `id: int` 索引，无法用序列号选设备
2. `composed_camera.py:375-379` 不透传 `device_id`
3. 强制开 depth 流，浪费 USB 带宽

需补：`RealSenseConfig` 加 `enable_depth: bool = False` 和 `serial_number: str | None = None`；`composed_camera.py` 的 `realsense` 分支透传 serial。

**[gear_sonic/data/features_sonic_vla.py:372-395](../gear_sonic/data/features_sonic_vla.py#L372-L395)** —— `get_wrist_camera_features` / `get_wrist_camera_modality_config` 加 `left/right` 参数，拆 `--record-wrist-cameras` 为 `--record-left-wrist` + `--record-right-wrist`。

**Jetson 装 pyrealsense2**：aarch64 没预编译 wheel，需从源码编 librealsense，**必加** `-DFORCE_RSUSB_BACKEND=true`（规避 Jetson 内核 uvc 冲突）。

### 启动

```bash
python -m gear_sonic.camera.composed_camera \
    --ego-view-camera usb --ego-view-device-id 0 \
    --ego-view-stereo-mode left --ego-view-capture-dim 1280 480 \
    --left-wrist-camera realsense --left-wrist-device-id <D405_SERIAL> \
    --port 5555
```

### 微调

`UNITREE_G1_SONIC` embodiment 默认 video 只有 `ego_view`。要用 wrist 必须**自定义 modality**：
- `dataset/meta/modality.json` 增加 `left_wrist` 字段（自动由改造后 schema 生成）
- `gr00t/configs/data/embodiment_configs.py` 注册新 tag（或派生 `UNITREE_G1_SONIC` 加 `left_wrist`）
- 建议 LoRA fine-tune，避免破坏 N1.7-3B 原视觉 backbone

## 5. 关键代码读数据流（速查）

```
Jetson:  USB相机/OAK/D405 ──► composed_camera_server ──ZMQ:5555──┐
                                  (drivers/*.py)                  │
                                                                  ▼
Workstation: run_data_exporter.py ── ComposedCameraClientSensor ──┤
             ├── _add_images_to_frame_data()  ◄── 按 dataset_features 的 image_key 硬查
             └── 输出 LeRobot v2.1 dataset (parquet + mp4)
```

**关键约束**：[run_data_exporter.py:526-540](../gear_sonic/scripts/run_data_exporter.py#L526-L540) 对 schema 里每个 image 字段做硬断言。所以 schema 多一个 → 必须有；schema 少一个 → 相机服务多发的字段静默丢弃。

**推理消费**：[run_vla_inference.py:242-246](../gear_sonic/scripts/run_vla_inference.py#L242-L246)：
```python
video = {"ego_view": cam_img[...]}
if "left_wrist" in camera_msg["images"]:  video["left_wrist"] = ...
if "right_wrist" in camera_msg["images"]: video["wrist_view"] = ...  # 注意改名
```
ego_view 必有，腕部条件加入。**所以丢弃右腕在推理侧零改动**。

## 6. 不用腕部对数据采集的影响

| 项目 | 受影响？ |
|---|---|
| Proprio（joint/IMU/body_rot） | ❌ 不变 |
| Teleop 字段（smpl_*、wrist_joints[3]、hand_joints[7]） | ❌ 不变（这些是 SMPL 算的，与相机无关） |
| 录制频率 / 操作员手感 / VR 控制 | ❌ 不变 |
| Dataset 结构 | 仅少 `videos/observation.images.left_wrist/`、`right_wrist/` |
| 操作员 viewer 反馈 | ⚠️ 4 格变 1 格，**精细抓取易漏察觉失败 episode** |
| 模型可学的视觉细节 | ⚠️ 缺指尖近景，桌面级精操作建议多采 30-50% 数据 |

控制链路**完全不读相机** → 采集流程零损失。

## 7. 工程坑速查

| 现象 | 原因 | 解决 |
|---|---|---|
| USB 双目开不到 1280×480 | UVC 默认 YUYV | 设 `MJPG` fourcc |
| RealSense `No device connected` | udev 没装 / USB 供电不足 | `./scripts/setup_udev_rules.sh` + 直插 |
| Jetson D405 frame timeout | 内核 uvc 冲突 | librealsense 编译加 `FORCE_RSUSB_BACKEND=true` |
| `wait_for_frames` 第二次失败 | rs context 未释放 | `close()` 里 `del self.pipeline` |
| 推理 shape mismatch | checkpoint modality 与 dataset 不一致 | 对齐 `meta/modality.json` 与 embodiment_config |
| 三相机 USB 带宽不够 | 多路相机争抢 USB3 | 用有源 USB3 hub，OAK 开 MJPEG |

## 8. 决策树

```
任务是否需要看清指尖接触？
├── 否 → 方案 A（单头 USB 双目）
│         改 ~50 行、直接 finetune N1.7-3B、官方主线
└── 是 → 先跑 A，评估成功率
          ├── 够用 → 停在 A
          └── 不够 → 加 D405 升级到 B，LoRA 续训
```

**起步永远从 A 开始**：把整条数据流和 finetune 流程先单 view 跑通，再决定要不要加腕部视觉。
